## 长文：过去的重要对话，值得再问一次

每次模型更新，我们很容易去试一个新问题，却很少回头看那些曾经认真聊过、最后停在半路的事情。

一个项目当时做不动，可能是工具能力有限，也可能是模型从一开始就误解了目标。后来预算变了、你在另一段对话里补充了关键约束，旧方案却仍然停在原地。

理论上，我们可以把这些问题重新问一遍。实际困难是：你得记得它在哪里，判断值不值得重问，再写一段足够好的提示，告诉模型这次需要重新思考、验证和交付，而不只是继续往下聊。

我正在做一个开源 skill：Second Look。它想让这个过程更容易。你可以直接说：

> 看看我们以前聊过的事情，有没有现在能想得更好、做得更好的。

它会在当前环境真正能访问的历史里寻找值得重新处理的问题，找回目标和后续修正，再尝试交付 1—3 项可以使用的新版成果。没有可靠改进时，可以保留旧结论，不需要硬凑“惊喜”。

仓库里有一组不涉及个人数据的合成演示：一个被“需要 6000 元代理预算”卡住的访谈项目，在后续资源条件下重新形成了预算和工时算得通的试点；一个因不能上传笔记而停下来的搜索项目，变成了可以检查的离线原型；一份被写成融资推介的社区申请，回到用户要求的四个部分，完成正文。

这些是演示，不是真实用户效果数据。我们也用强普通复盘提示试了相同材料，它同样给出了可用成果。所以我并不想说“装上 skill，模型就一定变聪明”。更想验证的是：把找历史、保留证据、重新求解和记住处理结果做成可复用流程，能否让更多人稳定获得一次有价值的重新思考。

它也不只在模型更新时有用。项目重启、预算变化、反复沟通仍不满意、同一主题散在多段对话里，都是值得再看一次的时刻。首版没有默认后台提醒，也不自动监控模型发布。

当前是 MIT 开源预览版，提供 Codex、Claude Code 安装方式和受限环境的文本入口。能读取多少历史取决于宿主能力；没有额外开发者服务器或 API 服务，但读取的内容仍会经过你使用的模型服务。

如果你曾经和 AI 认真做过一件事，后来搁置了，可以先试仓库里的合成演示，再决定是否用于自己的历史。我尤其想知道：它有没有找回真正的目标？给出的新版成果你愿不愿意采用？有没有一件事根本不该被重新翻出来？
