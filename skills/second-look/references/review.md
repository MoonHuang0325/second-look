# Selection and reasoning

Seek evidence for four dimensions without an arbitrary weighted score:

- **Relevance:** recurring goal, explicit importance, reusable work, or relation to today's request. Closed/expired needs are usually poor candidates.
- **Gap:** blocker, unsupported premise, dissatisfaction, missed constraint, unresolved contradiction, or demonstrated defect.
- **Reason now:** new evidence/tools, changed circumstances, visible reasoning error, or an unexamined connection. Do not invent a model upgrade or project status.
- **Actionability:** revised answer, usable draft, simpler solution, or small experiment with present value.

Prioritize stronger evidence and useful outcomes. Explore older/unseen material but do not promote something solely for surprise. Solve strong candidates instead of spending the whole budget cataloging history.

Use stable goal IDs. Similar words do not make two client projects the same project. Later explicit corrections supersede old constraints for today's task; branches stay alternatives unless selected. Resolve conflict using current intent or state the unresolved fork.

## Task packet

Capture the goal/success criteria, current constraints with provenance, user facts versus independent evidence versus old assistant assumptions, unknowns, attempts, old artifact/conclusion, stopping point, related clues, and source locators/completeness. Preserve old constraints only when the change matters. Ask only for missing information that materially changes the result; do not ask users to repeat available facts.

## Verification

| Work | Meaningful check |
| --- | --- |
| Code | Reproduction or focused tests in an isolated workspace; observe original constraints. Label unexecuted patches untested. |
| Research | Current primary sources where time matters; separate inference and inaccessible references. |
| Writing | Complete revision against audience, purpose, mandatory facts, length and tone; subjective gains are choices. |
| Learning | Correct worked example addressing the actual misconception; do not claim unobserved learning outcomes. |
| Decisions | Feasibility against explicit resources/dependencies/tradeoffs; untested decisive assumptions remain hypotheses. |

Use domain-appropriate verification for high-impact conclusions. Unsupported medical/legal/financial claims do not become reliable by appearing in an old transcript.

A supported improvement requires an identifiable difference, evidence, and relevance to the goal. New evidence or constraints can create value without proving better model reasoning. Fluency, length, confidence, or novelty alone cannot establish improvement. Retaining a decision while improving its artifact is valid when the actual benefit is precise.

## Revisit conditions

Record observed model IDs only; unknown is null. A known different model may justify reconsideration; an unknown ID cannot. Record explicitly changed circumstances as revisit context; generic invocation wording is not a new circumstance.

`closed`/`exclude` suppress identified goals or sources until `include` reverses them. `accepted` and `dismissed` require explicit feedback. Never infer adoption from silence or convert a temporary choice into a personality rule. A specific request to reconsider an excluded item can override it for that run without changing its standing preference.
