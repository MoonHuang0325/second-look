# Second Look 发布与运营行动手册

目标：让真正有重要 AI 对话的人看见它、完成一次复盘、采用一个成果，并愿意再次使用。Star 是传播结果之一，不是有效性的证明，也不能保证“现象级”。

本手册对应 v0.2.0 预览版。对外统一入口：[项目首页](https://github.com/MoonHuang0325/second-look)。第一次体验推荐合成演示；对真实历史的访问能力按宿主说明。

## 已准备的东西

- 中英文首页、一句话调用、三份实际生成的完整演示、安装和升级回退说明。
- 不读取个人历史的演示包；标准 skill、OpenAI 插件包装和推广素材包。
- 强普通提示与 skill 的两次独立开发试跑，公开两边成果和局限，不宣称胜出。
- 问题反馈入口、贡献指引、兼容矩阵、24 组合成行为案例与用户试用方案。
- [中文长短文](copy.zh-CN.md)、[英文发布文案](copy.en.md)、[60 秒演示脚本](recording-script.zh-CN.md)、[指标空表](metrics-template.csv)。

这些文件是发布草稿，不表示已经发到任何社交账号。没有用户证言、真实采纳率、完成的两周试用或平台官方背书。

## 首轮建议：小范围证明“值得再来”，再扩大传播

不要同时追逐所有平台。先在你已经参与、且允许分享工具的一个中文社区发布，再在一个英文开发者社区发布。普通用户看“之前卡住，现在拿到了什么”；开发者另外看代码、证据和边界。选择社区前阅读当时的发布规则，不群发、不组织点赞、不购买 Star。

| 时间 | 你来做什么 | 交付与判断 |
| --- | --- | --- |
| 第 1–2 天 | 在自己常用的宿主跑一遍合成演示；录 60 秒真实操作 | 有清楚的输入、输出、检查过程；失败也记录。发现安装阻塞先修复。 |
| 第 3–4 天 | 邀请 5 位知识工作者、5 位开发者独立试用 | 原文留在各自环境，只收同意分享的最少反馈；不是要求给 Star。 |
| 第 5–7 天 | 在一个已有关系的中文渠道发布；当天安排时间回复 | 使用一份具体成果和一条入口，记录访问、安装问题、首轮结果。 |
| 第 2 周 | 修复最常见的安装或结果问题；发布一篇真实复盘 | 征得同意后才使用用户经历；没有真实案例就继续明确用合成案例。 |
| 第 3 周 | 完成 14 天回访，发布英文演示，视完成度提交 Show HN | 记录模型更新以外的自发复用；不要把回访提醒造成的使用称为自发。 |
| 第 4 周 | 公布样本量、失败案例和改动；决定下一轮投入 | 成果有用但找不到入口就改善入口；发现多、采纳少就改善求解。 |

运行期每周留两次固定维护时段即可，无须强行日更。首发后的前两天尽量及时处理安装失败。不要承诺无法持续兑现的回复时限。

## 三个需要你参与的环节

**真实发布。** 选择你愿意使用的账号与社区，检查草稿，再由你发布；本次没有代发。推荐先发中文长文或短文中的一个，附 60 秒演示和仓库链接。英文可随后使用同一份演示，避免在多个地方机械复制。

**真实试用。** 找到两类用户各至少 5 人。让他们在自己的模型宿主内跑，不收原始对话。按 [试用表](../../evals/pilot.md) 收集是否值得关注、是否愿意采用/验证、哪里失败。给评审者看去条件标签的成果，尽量隐藏哪份来自 skill；承认文风可能暴露条件。开发者自己的评价不能代替用户盲评。

**平台操作。** 若希望设置 GitHub 仓库的社交分享卡片，在仓库设置中上传 [social-preview.png](../../assets/social-preview.png)。图片已备好，但设置是否生效需你在界面确认。录屏和个人账号发布也需你完成。不要把有插件 ZIP 表述成已经上架市场；ChatGPT/Claude 原生上传与真实历史读取还需要相应账号逐项实测。

## 指标要分开记录

使用 [指标空表](metrics-template.csv) 和 [发布记录空表](launch-log-template.csv)，只填实际观察值，未知留空。

- **发现：** 哪个渠道带来访问、独立访问量、Star 净增。GitHub 流量窗口有限，至少每周保存一次；[GitHub 流量说明](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository)说明可查看最近 14 天数据。
- **启动：** 有多少参与者尝试安装、装好、完成第一次复盘。中途失败必须保留，不能从分母中静默删除。
- **价值：** 首轮完成者中，多少认为至少一项发现值得关注，多少愿意采用或验证成果。另报“所有启动者”的比例，显示安装损耗。意愿与实际采用分列。
- **复用：** 14 天内在模型更新以外场景主动再用的人数、是否因为提醒才使用、无关旧事被翻出造成的打扰。没有回访的数据不能当作零，也不能当作成功。

70% 发现率、50% 采用/验证意愿是待检验目标。10 人中 7 人肯定只是小样本观察，要公布人数和缺失反馈；不能推出所有用户都有效。Star 与试用采用率之间没有可直接归因的关系，不把一个比例命名成未经观测的“访问转化率”。

## 可以讲什么，不可以先讲什么

| 可以据实表达 | 还不能表达 |
| --- | --- |
| MIT 开源；无额外 API 服务；宿主使用其当前模型 | 全部本地推理、所有模型永久免费 |
| 合成案例中交付了可检查的计划、代码和正文 | 已帮助大量用户、节省 X 小时、必然带来突破 |
| 可访问范围内寻找历史，缺工具时用导出/可见文本 | 自动读取所有 ChatGPT/Claude 历史 |
| 两个独立开发试跑都得到可用成果 | 已证明 skill 优于强提示词或新模型更聪明 |
| 预览版；明确兼容项与未验证项 | 已获平台认证、已经上架所有市场 |

## 根据反馈决定下一版

优先处理：装不上 → 没读到必要原文 → 找错目标 → 只有总结没有新版成果 → 重复推荐已结束内容。每次修复配一个可复现的合成例子。用户没有新材料时不强推复盘，继续保留“没有可靠改进”的输出。

只有多位用户在两周内证明成果有用，并明确希望被提醒，才评估可选定期发现。不要为了保持曝光率提前加入后台扫描。长期内容可以围绕项目重启、预算变化、被误解的目标和跨对话线索展开，不依赖模型发布新闻。

## 发布当天检查

确认公开链接可打开、下载包可安装、演示标记为合成、兼容表准确、录屏没有账号信息、文案没有虚构数字。使用自己的实际经历时再补上第一人称体验；不要把提供的示例说成真实客户故事。按渠道规则发布，保留退出和负面反馈入口。

[Show HN 官方规则](https://news.ycombinator.com/showhn.html)强调应让读者能试用实际作品，并禁止拉票；准备好可运行演示后再考虑提交。真实记录失败并修复，比一轮集中索取 Star 更能积累长期信任。
