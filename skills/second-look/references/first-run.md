# First use

Start with the user's requested outcome. Do not turn a personal review into a demo, an account-wide access request, or a choice of modes.

- If the skill is installed and the user asks for a real review, discover the host's history tools and work within actual scope. Give one short coverage sentence. Reuse known relevant history rather than repeating setup questions.
- If using a local helper is appropriate, `python3 scripts/second_look.py capabilities --local` reports Python/helper version and candidate folder existence without reading transcripts. This does not check that history is complete or that native tools work.
- If the user asks to try the skill without private data, read `../assets/demo/START.md` and `../assets/demo/history.md` relative to this reference, or have the helper's `demo --output <new-folder>` copy the pack. Read the start request and deliver the work. Do not claim that indexing the pack is running the model.
- For a host with no history access, use useful currently visible evidence. If none is sufficient, ask for one transcript or export, naming the missing capability plainly. Avoid instructions to export an entire account when one project is enough.
- After a real result, mention exclusions or persistence only when useful. Do not ask for a rating, a Star, or a share as a condition of receiving the result.

For a first-use check, observe installation recognition, actual source access, source-grounded output, and what happens on a repeated run separately. A sample-only check cannot establish personal-history discovery.
